FlyRank Capstone — Refresh-Priority Model

Author: Pavithra Sivakumar

Lane: Machine Learning

Repository: GitHub repository

0. Abstract

This capstone asks which pages from a client's existing content should be prioritized for a refresh review. The analysis uses the FlyRank content-refresh dataset and evaluates signals associated with page performance and refresh priority. The project develops and evaluates a machine-learning approach against a transparent baseline. The resulting score is intended to support a ranked editorial review queue. The output is decision support for prioritizing content review rather than a claim about any search-engine ranking algorithm.

1. Problem framing

The decision supported by this project is:

Among a client's existing content, which pages should an editor prioritize for a refresh review?

The unit of analysis is an individual content page. The model produces a decline-risk score for each page and uses that score to create a ranked action queue.

A false positive may cause an editor to spend time reviewing content that does not require a refresh, while a false negative may cause a genuinely declining page to be overlooked.

Machine learning is useful because the dataset contains multiple signals about content, visibility, engagement, search demand, and other page characteristics that can be combined into a single decision-support score.

2. Data safety

The project uses the local FlyRank content-refresh dataset available in the repository. Pseudonymous client identifiers are used only for grouping and evaluation where required and are not used as predictive features.

Label-derived fields such as trend_direction and trend_pct are excluded from model features to reduce leakage risk. Client-identifying information is not intentionally included in the deployed paper.

3. Baseline

The project first establishes a transparent baseline so that the machine-learning model can be compared against a simple decision rule. The baseline and model are evaluated on the same evaluation split and using the same task metrics.

4. Model / analysis

The capstone uses a supervised machine-learning approach to estimate page-level refresh priority. Features are selected from information available before the decision and label-derived information is deliberately excluded.

The target represents the page-level refresh-priority outcome defined by the capstone dataset and analysis.

5. Evaluation

Evaluation follows the split and validation procedure implemented in the capstone notebook. Model performance is compared with the baseline on the same evaluation data.

The detailed metrics, validation checks, and error analysis are recorded in the capstone notebook and repository outputs.

6. Interpretation

The model is interpreted as a decision-support system for identifying pages that may deserve earlier editorial attention. Feature-level analysis is used to understand which available signals contribute to the model's decisions.

These results should be interpreted as observed predictive patterns in the dataset, not as causal effects.

7. Recommendation

The recommended workflow is to rank existing pages by the model's refresh-priority score and have editors review the highest-priority pages first.

The score should be treated as decision support rather than an automatic publishing or deletion decision. Human review remains necessary, particularly for borderline predictions and unusual pages.
